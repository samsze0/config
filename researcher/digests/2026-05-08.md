# Research Digest: 2026-05-08

## Executive Summary

Current primary sources reinforce the repo's existing direction: keep persistent instructions compact, use retrieval and skills deliberately, preserve durable handoff artifacts, delegate only across clean boundaries, and treat evaluation as a first-class harness feature rather than an afterthought [S1][S2][S5][S6][S7][S8].

The most actionable new signal is that long-running agent systems should separate durable session history, the orchestration harness, and sandboxes/tools so harness assumptions can change as models improve without losing state or exposing credentials [S1]. Evaluation guidance also tightened: SWE-bench Verified is now considered contaminated for frontier coding claims by OpenAI, and Anthropic found that infrastructure configuration alone can move agentic coding benchmark scores by several percentage points [S3][S4]. The digest should therefore push this repo toward reproducible, environment-aware eval notes rather than static leaderboard trust [S3][S4][S5].

## Findings

### Durable Sessions Should Be Separate From Context Windows
- **What changed**: Anthropic's Managed Agents write agent activity to an append-only durable session log, keep the harness restartable, and treat sandboxes/tools as replaceable execution targets; their design explicitly separates recoverable session history from whatever context subset is currently passed to the model [S1].
- **Why it matters for this harness**: The repo already values compact persistent context and artifact-based handoff. The newer pattern says the durable source of continuity should be an inspectable event or artifact log, not only compaction summaries or the active conversation window [S1][S8].
- **Recommended implication**: Add future harness guidance that distinguishes three layers: persistent repo instructions, durable task/session artifacts, and transient model context. For long tasks, require a handoff artifact or event log that a fresh agent can query before relying on summary compaction [S1][S8].
- **Confidence**: High
- **Sources**: [S1][S8]

### Harness Scaffolding Must Be Revalidated Per Model Generation
- **What changed**: Anthropic reports that context resets helped Claude Sonnet 4.5 avoid premature wrap-up near context limits, but the same reset scaffold became unnecessary with Claude Opus 4.5; their March 2026 long-running app harness also shows planner/generator/evaluator loops can improve complex app quality but at much higher runtime and token cost [S1][S2].
- **Why it matters for this harness**: The README already says harnesses should be revisited as models improve. Current evidence sharpens that into a maintenance rule: scaffolding encodes assumptions about model weakness, and those assumptions can become dead weight [S1][S2].
- **Recommended implication**: When changing the selected backend model, run a small harness smoke eval before preserving or expanding scaffolding. Keep decomposition, context resets, evaluator agents, and delegation as measured interventions, not permanent defaults [S1][S2].
- **Confidence**: High
- **Sources**: [S1][S2]

### Coding-Agent Benchmarks Need Environment And Contamination Controls
- **What changed**: OpenAI states that SWE-bench Verified no longer measures frontier coding capability reliably because of contamination and flawed remaining test cases, and recommends SWE-bench Pro instead [S4]. Anthropic separately found Terminal-Bench 2.0 success changed by up to 6 percentage points between strict and uncapped resource configurations, with resource limits changing what strategies agents could use [S3].
- **Why it matters for this harness**: This repo's cited-source intake should avoid turning benchmark names into universal proof. For agentic evals, the model, scaffold, tools, hardware, time limits, retries, and benchmark freshness all affect the measured result [S3][S4][S5].
- **Recommended implication**: Add an evaluation-reporting checklist before incorporating benchmark claims: benchmark date/version, contamination status, task selection, number of attempts, sandbox resources, time limits, network/dependency policy, pass/fail graders, and residual failure categories [S3][S4][S5].
- **Confidence**: High
- **Sources**: [S3][S4][S5]

### AGENTS.md Should Carry Compressed Retrieval Cues, Not Full Manuals
- **What changed**: Vercel's Next.js eval found a compressed 8KB docs index in `AGENTS.md` reached 100% pass rate, while default skill usage matched baseline and skill usage with explicit instructions reached 79% [S6]. Chroma's long-context report found performance becomes less reliable as input length grows, even when only context length changes [S7].
- **Why it matters for this harness**: The repo's current balance is correct but should stay narrow: persistent context should remove critical retrieval decision points, while deeper workflows and volatile manuals stay in skills or docs [S6][S7][S8].
- **Recommended implication**: Keep `AGENTS.md` as a compact bootstrap plus high-value indexes. For project/framework knowledge, prefer short retrieval maps and mandatory read triggers over embedding full content [S6][S7][S8].
- **Confidence**: High
- **Sources**: [S6][S7][S8]

### Agent QA Should Evaluate Outcomes, Traces, And Tool Trajectories
- **What changed**: Anthropic's eval guidance defines agent evals around tasks, trials, graders, transcripts, outcomes, evaluation harnesses, and agent harnesses; it emphasizes that final claims can diverge from environment state [S5]. Google ADK documents evalsets with expected tool use, reference responses, user simulation, CLI evaluation, and criteria for tool trajectories, response quality, hallucination, and safety [S9]. LangChain argues that production traces are the source of truth for debugging agent reasoning and can seed regression datasets [S10].
- **Why it matters for this harness**: Independent evaluation should not stop at "the agent said it worked." Coding-agent QA needs observable outcome checks, tool/command traces, and regression cases harvested from real failures [S5][S9][S10].
- **Recommended implication**: For long-running or delegated work, define acceptance criteria at three levels: final repo state, trace/tool behavior for known risks, and human or evaluator review for subjective quality [S5][S9][S10].
- **Confidence**: High
- **Sources**: [S5][S9][S10]

### Parallel Agents Are Useful, But Only With Clear Ownership And Cost Awareness
- **What changed**: OpenAI's Codex app positions parallel agents, isolated worktrees, and long-running task supervision as core coding workflows [S11]. Anthropic's multi-agent and harness posts show planner/generator/evaluator and orchestrator-worker patterns can improve breadth or QA, but cost and coordination overhead rise sharply [S2][S12].
- **Why it matters for this harness**: The repo's bounded-delegation rule remains current. Parallelism is increasingly productized, but sources still support using it where work splits cleanly, not as a default for tightly coupled edits [S2][S11][S12].
- **Recommended implication**: Keep delegation rules explicit: independent branch, disjoint write scope or research question, expected artifact, owner, and integration checkpoint. Track wall-clock, token, and review cost where possible [S2][S11][S12].
- **Confidence**: Medium
- **Sources**: [S2][S11][S12]

## Watchlist

- **Time-horizon evals as planning input**: METR's April 2026 page updates task-completion time horizons for frontier agents on more than one hundred software, ML, and cybersecurity tasks. This is useful for deciding how ambitious autonomous tasks should be, but the metric is task-duration-based and not a guarantee that agents can handle high-context professional work of the same calendar length [S13].
- **Developer-productivity measurement is moving**: METR's February 2026 update says its late-2025 developer productivity experiment became hard to interpret because developers increasingly avoided no-AI conditions and often used multiple agents concurrently. This is a signal to watch, not a workflow rule by itself [S14].
- **Agent interoperability standards**: Google Cloud's A2A v0.3 announcement and Google ADK's multi-agent primitives suggest more standard patterns for agent-to-agent and workflow-agent composition. Watch for maturity, security, and adoption before adding A2A-specific repo guidance [S9][S15].
- **Managed-agent security boundaries**: Anthropic's separation of harness, session, sandbox, credential vault, and MCP proxy is relevant if this repo later grows from workflow guidance into an executable harness [S1].

## Do Not Incorporate Yet

- **Do not replace skills with `AGENTS.md` wholesale**: Vercel's eval supports compressed persistent retrieval cues for framework knowledge, but it also says skills remain useful for vertical action-specific workflows. This repo should keep the skill-first workflow while improving trigger cues and indexes [S6].
- **Do not report SWE-bench Verified as frontier proof**: OpenAI recommends against using SWE-bench Verified for frontier coding capability claims because contamination and remaining test-design problems now dominate the signal [S4].
- **Do not add unconditional multi-agent fan-out**: OpenAI and Anthropic show stronger tooling for parallel agents, but Anthropic also documents high costs for full planner/generator/evaluator harnesses and warns that scaffolding needs revalidation as models improve [S1][S2][S11].
- **Do not treat bigger context windows as a substitute for retrieval discipline**: Chroma and Anthropic both argue that long context remains failure-prone and finite, so the harness should continue preferring high-signal context, compaction, memory artifacts, and just-in-time retrieval [S7][S8].
